# 2026-09-12 — 포털 초기 구현

## 한 일

게임 포털을 처음부터 만들어 배포했다. 범위는 포털 껍데기까지이고,
게임 저장소(`MergeDrop`, `phaser-starter`)는 한 줄도 건드리지 않았다.

- 게임 레지스트리, 해시 라우팅, 카드 그리드, 최고 점수 표시, 3상태 테마 토글
- 빌드 설정·배포 워크플로·린트 설정은 `phaser-starter`에서 그대로 복사 (Phaser 의존성만 제거)
- 테스트 21개 (라우팅, 레지스트리 검증, 점수·메시지 검증)
- 번들 gzip 3.45KB — 목록이 즉시 뜨는 게 이 방식의 유일한 위안이라 프레임워크를 넣지 않았다

등록한 게임은 이미 배포되어 있던 실제 게임 2개다. 가짜 placeholder보다 iframe 경로를
확실히 검증할 수 있고, 어차피 게임 쪽에는 아무 변경이 없다.

## 구현 중 실제로 걸린 문제

### iframe이 150px로 찌그러졌다

게임을 띄웠는데 검은 띠만 보였다. `.stage`는 `flex: 1`로 690px인데 iframe은 150px였다.

`height: 100%`가 **flex로 크기가 정해진 부모에 대해서는 해석되지 않아** iframe이 자기 기본
높이(150px)로 떨어진 것이다. 브라우저마다 다르게 동작하는 회색 지대라 더 나쁘다.

`.stage`가 이미 `position: relative`였으므로 iframe을 `position: absolute; inset: 0`으로
바꿔 해결했다. 퍼센트 높이에 기대지 않는 쪽이 확실하다.

### 점수가 안 나온다고 착각했다

localStorage에 값을 심고 확인했는데 카드가 계속 "기록 없음"이었다. 코드를 한참 봤지만
`readBest()`를 직접 호출하면 정상적으로 값을 돌려줬다.

원인은 코드가 아니라 검증 방법이었다. 브라우저 도구의 `navigate`가 **같은 URL이라 실제
문서를 다시 읽지 않아서** 화면이 값을 심기 전 상태 그대로였다. `location.reload()`로
강제 리로드하니 `최고 4,210점`이 정상 표시됐다.

교훈: 같은 주소로 "다시 이동"한 것을 리로드로 착각하지 말 것. 콘솔 로그가 지워지지 않은 것이
단서였다.

## 확인한 것

- 목록 → 카드 클릭 → MergeDrop이 iframe 안에서 실제로 플레이됨(클릭 입력, 물리 동작)
- 뒤로가기 → 목록 복귀, iframe이 DOM에서 사라짐, `is-playing` 해제
- `<id>.best`와 `scoreKey` 예외 양쪽 모두 카드에 표시됨
- 테마 토글 즉시 반영 + 새로고침 후 유지
- 375px에서 1열, 가로 스크롤 없음
- `#/game/nope` → "없는 게임입니다"
- `GITHUB_REPOSITORY=eastaim/games`로 빌드하면 에셋 경로가 `/games/`로 나옴

## 남은 것

- **`phaser-starter` 템플릿의 점수 키가 `game.best`다.** 게임 공용 키라서 이 템플릿으로 만든
  게임이 둘 이상 배포되면 같은 오리진에서 서로의 최고 점수를 덮어쓴다. 지금은 포털이
  `scoreKey: 'game.best'`로 우회하고 있지만, 템플릿을 `<id>.best`로 고치는 게 맞다.
- **MergeDrop 캔버스가 화면 중앙에 오지 않는다.** 포털 밖에서 직접 열어도 같으므로 게임 자체
  문제다. 포털과 무관하다.
