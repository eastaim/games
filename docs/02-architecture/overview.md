# 아키텍처 개요

포털은 정적 사이트다. 백엔드도, 프레임워크도, 빌드 시점의 게임 의존성도 없다.

## 데이터 흐름

```
location.hash
   ↓  core/router.ts   parseRoute(hash, 알려진 id 집합)
Route
   ↓  catalog/games.ts  findGame(id)
GameEntry
   ↓  ui/ListView.ts | ui/GameView.ts
DOM
```

한 방향으로만 흐른다. 뷰는 라우트를 읽고 그릴 뿐, 라우트를 직접 바꾸지 않는다
(카드는 그냥 `<a href="#/game/...">`이고, 나머지는 `hashchange`가 처리한다).

## 계층

| 디렉터리       | 역할                                     | DOM      |
| -------------- | ---------------------------------------- | -------- |
| `src/catalog/` | 게임 목록 — 데이터                       | 안 씀    |
| `src/core/`    | 라우팅·점수·테마·신원·저장소 — 순수 로직 | 안 씀    |
| `src/ui/`      | 화면                                     | 여기서만 |
| `src/main.ts`  | 조립 — 라우터 구독, 뷰 교체              | —        |

`core/`와 `catalog/`가 DOM을 쓰지 않는 것이 핵심이다. 덕분에 라우트 표 전체, 점수 판정,
postMessage 검증을 브라우저 없이 vitest로 테스트한다. 이 경계가 무너지면 테스트가 불가능해진다.

게임 프로젝트의 `src/game/`(Phaser 미의존 순수 규칙)과 같은 원칙이다.

## 게임 레지스트리

`src/catalog/games.ts`가 게임 목록의 유일한 출처다. 새 게임은 항목 하나.

```ts
{ id, title, tagline, path, accent, status, scoreKey? }
```

- `id` — 라우트(`#/game/<id>`)이자 점수 키(`<id>.best`)의 근거. `[a-z0-9-]+`
- `path` — 배포된 게임의 Pages 경로. 앞뒤 슬래시 필수
  (슬래시가 없으면 Pages가 리다이렉트하고, iframe 안의 리다이렉트는 포커스를 잃기 쉽다)
- `scoreKey` — 규약보다 먼저 만들어진 게임을 위한 예외. **게임을 고치는 대신 포털이 맞춘다**
  (2026-09-12 기준 이 예외가 필요한 게임은 없다. phaser-starter가 `<id>.best`로 재배포되면서
  `game.best` 우회를 제거했다. 규약보다 앞서 배포된 게임이 다시 생길 때를 위해 필드는 남긴다)

### 게임 URL 계산

```ts
const host = import.meta.env.DEV ? 'https://y3games.github.io' : location.origin;
```

배포 환경에서 `location.origin`을 쓰는 이유는 **같은 오리진이어야 최고 점수를 읽을 수 있기**
때문이다. 로컬 개발에는 localhost에 게임이 없으므로 실제 호스트를 가리킨다 — 게임은 뜨고
플레이도 되지만 교차 오리진이라 점수는 보이지 않는다. 의도된 동작이다.

## 플레이어 신원

게임이 만든 `player` 쿠키(`{"id","name"}`, `path=/`)를 포털이 같이 읽는다. 오리진이 하나이므로
포털과 모든 게임이 같은 사람으로 인식한다. 점수 키가 게임마다 갈라지는 것과 정반대다.

| 저장 위치                           | 범위        | 값                           |
| ----------------------------------- | ----------- | ---------------------------- |
| 쿠키 `player` (+ localStorage 미러) | 오리진 전체 | `{"id":"<uuid>","name":"…"}` |
| `<id>.best`                         | 게임 하나   | 숫자 하나                    |

형식 정의는 게임에서 import하지 않고 `core/player.ts`에 복제한다. 이유와 트레이드오프는
[ADR-002](adr-002-플레이어-신원-공유.md)에 있다. 인증이 아니므로 이 값으로 권한을 주지 않는다.

## 라우팅

해시 라우팅이다. 프로젝트 경로 Pages 배포에는 경로를 다시 쓸 서버가 없으므로,
새로고침을 견디는 딥링크는 해시뿐이다.

- `#/` — 목록 (`''`, `'#'`, `'#//'`도 모두 목록으로 본다)
- `#/game/<id>` — 게임
- 그 외 · 모르는 id — "없는 게임입니다". 조용히 목록으로 보내지 않는다(북마크가 깨진 것을
  알려야 한다)

`parseRoute()`는 알려진 id 집합을 **인자로 받는다**. 카탈로그를 import하지 않으므로 순수하게
유지되고, 테스트는 실제 게임 목록 대신 픽스처로 구동한다.

## 게임 실행

`ui/GameView.ts`가 iframe을 마운트하고, `destroy()`가 그것을 되돌린다.

나갈 때는 **iframe 엘리먼트를 DOM에서 제거한다**. `src`를 비우는 방식은 게임의 렌더 루프,
오디오, 타이머가 목록 뒤에서 계속 돈다. 엘리먼트를 지우면 문서째로 정리된다.

`sandbox`는 걸지 않는다. 내 게임이고 같은 오리진이며, `allow-same-origin` 없이 sandbox를 걸면
게임이 자기 localStorage에서 끊겨 모든 카드가 "기록 없음"이 된다.

## 점수

포털과 게임이 같은 오리진이므로 게임의 최고 점수는 이미 같은 localStorage에 있다.
포털은 그것을 읽기만 한다 — **쓰지 않는다.** 숫자의 주인은 게임이고, 사본을 만들지 않는다.

`core/storage.ts`가 localStorage에 닿는 유일한 지점이다. 시크릿 모드, 사이트 데이터 차단,
임베드 환경에서 접근 자체가 예외를 던질 수 있어 모든 접근을 try/catch로 감싼다.
기록이 없으면 `null`을 돌려주고 UI는 "기록 없음"이라 적는다 — 없는 0점을 보여주지 않는다.

### postMessage (선택)

게임이 플레이 중에 점수를 올려보내면 새로고침 없이 카드가 갱신된다. 지금 보내는 게임은 없고,
보내지 않아도 된다. 받는 쪽은 `parseScoreReport()`가 **오리진을 먼저 확인하고 모든 필드를
타입 검사**한다. 임베드된 무엇이든 이 창에 메시지를 보낼 수 있으므로 검증 없이 믿지 않는다.

## 테마

`system` / `light` / `dark` 3상태. `system`은 상태의 부재가 아니라 하나의 상태다 —
OS 설정이 바뀌면 계속 따라간다.

CSS는 라이트를 기본으로 두고 다크를 **두 번** 정의한다: `prefers-color-scheme`용과
`[data-theme="dark"]`용. 미디어 쿼리 안에만 정의된 색은 수동 토글로 되돌릴 수 없다.

게임 iframe 내부는 테마를 따르지 않는다. 각 게임이 자기 배경을 그린다.
